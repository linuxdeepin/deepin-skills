# Eval: 单一源码兼容 v20/v25

## 任务

一个应用使用同一套 C++ 源码分别在 v20 和 v25 DTK5 环境构建。某个新 API 只在
较新的 DTK5 头文件中存在。请说明如何组织条件编译，以及哪些差异应改用运行时
判断。

## 期望输出

1. 不用 `DTK_VERSION_MAJOR == 5` 或 `QT_VERSION_MAJOR == 5` 判断 v20，因为两个
   系统都可能使用 DTK5/Qt5。
2. 优先使用 DTK 类/能力宏或构建期特性探测；没有能力宏时，按该 API 的真实引入
   版本使用完整 `DTK_VERSION`/`DTK_VERSION_CHECK()`。
3. 把头文件、符号、重载和依赖差异放在编译期适配点，不要求同一二进制跨系统。
4. daemon、缓存路径、显示后端等共同可编译但行为不同的能力，使用
   `DSysInfo`、introspection 和运行环境判断。

## 验证要点

- [ ] 没有把 DTK5 等同于 v20
- [ ] 使用完整 DTK 版本或能力检测隔离 API
- [ ] 区分编译期 API 差异与运行时环境差异
- [ ] 没有要求每个业务模块重复解析系统版本
