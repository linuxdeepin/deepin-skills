# Eval: 分组名与结果名的国际化

## 任务

用户的插件界面文案在中文系统下显示正常，但切换到英文系统后分组标题和结果名称仍显示中文。请分析原因并给出解决方案。

## 期望输出

回答应：
1. 指出 daemon 与前端对 `group`/`name` 只做透传，不做翻译
2. 说明内置分组名有翻译映射表，自定义分组名原样显示
3. 指出插件必须自行负责 `group` 与 `name` 的本地化
4. 给出 Qt 翻译方案：源码用 `tr()`/`QCoreApplication::translate()`，生成 `.ts` 并用 `lupdate`/`lrelease` 编译为 `.qm`
5. 说明 `.qm` 需随插件安装并加载（`QTranslator`），按系统语言选择
6. 说明 daemon 可能以 `LANG`/`LC_ALL` 之外的方式运行，建议按 `QLocale::system()` 判断语言

## 验证要点

- [ ] 指出框架只透传、不翻译自定义分组名
- [ ] 明确指出插件需自行本地化 `group` 与 `name`
- [ ] 给出 `tr()` + `.ts`/`.qm` 的 Qt 翻译流程
- [ ] 说明 `.qm` 的安装与加载方式
- [ ] 未建议修改 daemon 或前端来适配插件文案

## 评分标准

| 等级 | 条件 |
|------|------|
| ✅ **PASS** | 准确定位为插件侧国际化缺失，并给出完整的 Qt 翻译方案与加载方式 |
| ⚠️ **PARTIAL** | 指出需自行翻译但未给出 `.ts`/`.qm` 流程或加载方式 |
| ❌ **FAIL** | 声称 daemon 会翻译分组名，或建议把文案改成英文硬编码 |

## 反模式检查

- [ ] 未声称 daemon/前端会翻译自定义分组名
- [ ] 未建议用硬编码英文替代国际化
- [ ] 未建议修改 `dde-grand-search` 源码来适配插件
