# Eval: 内置搜索项冲突与 Name 命名

## 任务

用户想把插件命名为 `com.deepin.dde-grand-search.file-deepin`，因为「这样看起来更像系统内置功能，用户更信任」。请评估这个命名方案。

## 期望输出

回答应：
1. 明确指出该名称与内置文件搜索项冲突，会导致插件 `.conf` 被 daemon **直接忽略**
2. 说明 `PluginLoader` 会在加载时比对内置搜索项名称列表，冲突时只打印 warning 并跳过
3. 给出正确的命名建议：使用 `com.<公司>.<应用>.<功能>` 形式，如 `com.example.MyFileSearch`
4. 列出其他已占用的内置名称（至少几个），提醒避免
5. 说明 `Name` 同时是结果项 `searcher` 字段的值与 `OpenWithPlugin` 路由依据，必须唯一

## 验证要点

- [ ] 明确指出该名称会导致插件被忽略
- [ ] 说明冲突的判定发生在加载阶段且只记 warning
- [ ] 给出符合 `com.company.app.xxx` 规范的替代命名
- [ ] 列出若干内置搜索项名称
- [ ] 说明 `Name` 唯一性要求及其作为路由标识的作用

## 评分标准

| 等级 | 条件 |
|------|------|
| ✅ **PASS** | 明确否定该命名并解释被忽略的机制，给出合规替代方案 |
| ⚠️ **PARTIAL** | 指出不合适但未说明会导致插件被忽略，或未给出替代命名 |
| ❌ **FAIL** | 认可该命名，或声称可以通过其他配置绕过冲突 |

## 反模式检查

- [ ] 未认可冒用内置名称的方案
- [ ] 未声称重名时 daemon 会选择其一而非跳过
- [ ] 未建议修改内置搜索项名称来「让路」
