# Eval: 选择运行模式与优先级

## 任务

用户有三个插件需求，请分别为它们选择合适的运行模式与优先级，并说明理由：

1. 一个需要预先加载索引的搜索插件，希望第一次搜索就很快
2. 一个搜索开销很小的插件，用完就不需要常驻
3. 搜索能力是某个已经常驻运行的应用的一部分

## 期望输出

回答应：
1. 需求 1：`Auto` + `Priority=0`（High），daemon 启动时常驻启动并守护
2. 需求 2：`Auto` + `Priority=2`（Low），搜索时启动，不守护，空闲后退出；或 `Trigger` 模式按需拉起
3. 需求 3：`Manual` 模式，由应用自身控制服务启动，daemon 只调用接口
4. 说明 `Priority` 仅在 `Auto` 模式下有效
5. 说明 High/Middle 会被守护（异常退出自动重启，最多 3 次），Low 不守护
6. 若建议 Trigger 模式，需说明还需安装 `/usr/share/dbus-1/services/` 下的 `.service` 文件

## 验证要点

- [ ] 需求 1 选择 Auto + High（0），理由是 daemon 启动即常驻、首次搜索无冷启动
- [ ] 需求 2 选择 Auto + Low（2）或 Trigger，并说明不守护/按需启动
- [ ] 需求 3 选择 Manual，说明由外部控制启动
- [ ] 指出 `Priority` 仅对 Auto 模式有效
- [ ] 说明守护与重启次数限制
- [ ] 若推荐 Trigger，提到 `.service` 文件要求

## 评分标准

| 等级 | 条件 |
|------|------|
| ✅ **PASS** | 三个需求的模式与优先级选择全部合理，理由与源码行为一致 |
| ⚠️ **PARTIAL** | 选择基本正确但遗漏 `Priority` 仅对 Auto 有效，或未说明守护机制 |
| ❌ **FAIL** | 为 Manual 模式指定 `Priority` 并声称生效，或模式选择与需求矛盾 |

## 反模式检查

- [ ] 未声称 `Priority` 对 Manual/Trigger 模式生效
- [ ] 未声称 Auto 模式的进程重启次数无限制
- [ ] 未把 Manual 模式描述为由 daemon 启动进程
