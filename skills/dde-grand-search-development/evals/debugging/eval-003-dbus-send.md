# Eval: 用 dbus-send 隔离验证插件接口

## 任务

用户的插件看起来一切正常（进程在运行、日志无报错），但全局搜索始终没有结果。请给出用命令行隔离验证插件 DBus 接口的方法。

## 期望输出

回答应：
1. 给出 `dbus-send` 调用 `Search` 的完整命令（`--session`、`--dest`、对象路径、`接口名.Search`、JSON 参数）
2. 给出调用 `Stop` 与 `Action` 的命令
3. 说明如何确认服务已注册（`ListNames` 或 `d-feet`）
4. 说明如何用 `Introspect` 核对接口名与方法签名
5. 说明隔离验证的意义：`dbus-send` 正常而界面无结果 ⇒ 问题在结果 JSON 或 conf 配置，而非业务逻辑
6. 说明 JSON 参数需要转义引号

## 验证要点

- [ ] 给出可执行的 `dbus-send --session --print-reply` 命令
- [ ] 命令中目标为 `接口名.Search`，参数为 `string:{...}` 形式的 JSON
- [ ] 覆盖 `Search`/`Stop`/`Action` 三个接口
- [ ] 提供了检查服务注册的方法（`ListNames` / `d-feet`）
- [ ] 提供了 `Introspect` 核对签名的方法
- [ ] 说明了隔离验证的推理逻辑

## 评分标准

| 等级 | 条件 |
|------|------|
| ✅ **PASS** | 命令可直接执行且正确，并说明了隔离验证如何缩小问题范围 |
| ⚠️ **PARTIAL** | 命令基本正确但遗漏 `--session` 或转义错误，或未说明推理逻辑 |
| ❌ **FAIL** | 使用了系统总线（缺少 `--session`），或命令语法错误无法执行 |

## 反模式检查

- [ ] 未遗漏 `--session`（否则会打到系统总线，必然失败）
- [ ] 未使用错误的方法名大小写（如 `.search`）
- [ ] 未跳过隔离验证直接建议重装或重编译
