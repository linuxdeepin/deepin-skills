# Eval: 实现可中断的 Search

## 任务

插件的搜索需要扫描本地数据库，耗时可能达到数秒。请实现 `Search` 与 `Stop`，要求 `Stop` 被调用后正在执行的 `Search` 能尽快返回。

## 期望输出

回答应：
1. 用原子标志或加锁的集合记录被中断的任务号
2. `Search` 在搜索循环中周期性检查中断标志并提前返回
3. `Stop` 解析 JSON 取出 `mID`，标记该任务中断，返回 `true`
4. 说明 daemon 的超时为 25 秒，超时按无结果处理
5. 说明不要用同步阻塞等待，以免占住事件循环导致 DBus 无法响应 `Stop`
6. 说明 daemon 在同一插件上一次搜索未结束时会跳过新搜索

## 验证要点

- [ ] 使用了原子类型或互斥锁保护的共享状态记录中断
- [ ] `Search` 在循环中检查中断标志，而不是等全部算完
- [ ] `Stop` 从 JSON 中取 `mID`，按任务号粒度标记中断
- [ ] 提到 25 秒超时约束
- [ ] 指出同步阻塞会阻碍 DBus 响应 `Stop`
- [ ] 中断后返回空结果或部分结果，且结果 JSON 结构合法

## 评分标准

| 等级 | 条件 |
|------|------|
| ✅ **PASS** | 中断机制按任务号实现且搜索循环中生效，并说明了超时与阻塞风险 |
| ⚠️ **PARTIAL** | 实现了中断标志但仅在搜索结束后检查，或未说明 25 秒超时 |
| ❌ **FAIL** | `Search` 不可中断，或 `Stop` 未按任务号区分 |

## 反模式检查

- [ ] 未使用阻塞等待（`QEventLoop` 同步等待、`sleep`、`waitForFinished`）实现搜索
- [ ] 未在持有互斥锁期间做耗时计算
- [ ] 未把 `Stop` 实现为全局布尔标志而忽略 `mID`
