# GTK 主题适配

已有应用样式不能满足新主题的 GTK 配色时，按本页补充样式资源，并接入全局主题。目标产物是 GTK 亮暗子主题及其配置引用；图标、字体、光标和壁纸继续使用已选组合。

设置发布、Qt 调色板及 GTK 加载原理见 [主题生效机制](theme-mechanism.md)。这里生成的 CSS 供 GTK 使用，不能代替 Qt 的应用样式与调色板。

## 确定需要的适配

| 需求 | 处理方式 |
| --- | --- |
| 直接使用已有 GTK 外观 | 选择已有亮暗样式并填写 `AppTheme`，无需新增 CSS |
| 为新主题提供固定的亮暗配色 | 建立独立的 GTK 亮暗子主题，复用基础样式并覆盖目标颜色 |
| 用户以后可任意修改活动色 | 除固定样式外，还需要颜色到样式的更新能力及有效刷新方式 |

默认优先复用目标系统已安装的基础 GTK 样式，例如可用的 `deepin`、`deepin-dark`，在新子主题中完成配色。先确定支持 GTK 3、普通 GTK 4 还是 libadwaita，再选用对应样式规则；不能以一套 GTK 3 产物宣称全部支持。

## 子主题名称与全局配置

为亮暗样式使用两个独立名称，例如 `aurora-light`、`aurora-dark`。它们与全局主题 ID `aurora` 不同。使用 `dark` 后缀也便于兼容依靠名称识别暗色的 Qt/DTK 集成。

| 全局主题分组 | AppTheme | 配色要求 |
| --- | --- | --- |
| 默认分组 | `aurora-light` | GTK 活动背景与该分组的 `ActiveColor` 配套 |
| 暗色分组 | `aurora-dark` | 使用暗色背景、文字及对应活动色 |

单独填写 `ActiveColor` 不会自动重写 GTK CSS。亮暗 CSS 中需要有实际使用这些颜色的规则，并同时处理背景上的文字。

## 样式目录与依赖

用户子主题通常放在 `~/.local/share/themes/<子主题名>/`，系统子主题放在 `/usr/share/themes/<子主题名>/`。在每个子主题下按支持范围组织资源：

| 相对路径 | 用途 |
| --- | --- |
| `gtk-3.0/gtk.css` | GTK 3 普通样式入口 |
| `gtk-3.0/gtk-dark.css` | GTK 3 暗色变体入口；亮色子主题可在这里引用同系列暗色样式 |
| `gtk-3.0/assets/` | GTK 3 样式实际使用的附属资源，按需提供 |
| `gtk-4.0/gtk.css` 及对应资源 | 声明支持普通 GTK 4 时的独立产物 |

先导入对应基础样式，再覆盖目标颜色和必要的控件状态。导入不会复制基础资源，基础文件里的相对图片路径仍相对于基础文件解析，因此基础主题及其图片属于真实依赖。

同系列样式之间的引用也要在安装后有效。只填写子主题名称、只保留导入语句而缺少被引用文件，都不能构成可用样式。

部分 DDE 版本的识别要求还包括有效的 `gtk-2.0`、`gtk-3.0`、`metacity-1` 资源。按目标版本提供相应元信息和基础依赖，可引用已有的有效资源，不能用空目录替代。新样式应能被 Appearance1 的应用样式列表识别。

## 配色覆盖

先确认基础样式使用的命名色，再把全局主题的亮暗配色映射进去。GTK 3 基础样式中常见的对应关系如下，具体名称以所选样式为准：

| 颜色用途 | 常见命名色 |
| --- | --- |
| 活动背景 | `active_color` |
| 选中背景 | `theme_selected_bg_color`、`selected_bg_color` |
| 选中文字 | `theme_selected_fg_color`、`selected_fg_color` |

命名色只有被控件规则引用时才起作用。基础样式把文字或背景固定为某个颜色时，还需要覆盖对应的控件状态，不能只改命名色。

配色应同时覆盖正文与背景、选中与勾选、焦点、悬停、禁用及非活动状态。活动背景上的文字需保持可读；普通按钮可以保留自己的背景，不要求所有控件使用活动色。

标准字体、等宽字体、图标主题和光标主题继续由全局配置选择。GTK 配色适配应保留这些已有选择，避免在 CSS 中固定整套字体或替换组合资源。

## 接入与更新

1. 准备完整的亮暗样式文件及其依赖，放到目标 GTK 主题位置。
2. 确认两个子主题可被目标桌面识别，再将它们分别写入全局配置的 `AppTheme`。
3. 分别选择全局主题的亮暗模式，确认目标 GTK 应用使用对应样式，背景、文字和主要状态配套。
4. 在组合结果中列出子主题名称、支持的 GTK 版本、基础主题依赖和实际更新方式。

这些桌面查询与选择操作按名称使用 `deepin-desktop-environment` Skill 的 Appearance1 外观服务，具体接口由该 Skill 提供。

固定配色随子主题选择生效；任意活动色更新还需要将新颜色写入应用实际加载的样式。允许重启应用时，可以使用已明确加载的持久样式；要求运行中的应用实时更新时，还需要它们收到主题切换或样式重载。相关机制见 [主题生效机制](theme-mechanism.md)。

不要把新主题的固定配色默认写进用户全局 `gtk.css`，否则它可能继续覆盖其他主题。确需使用用户样式入口时，应保留已有内容，并让覆盖范围与用户要求一致。

没有专用 GTK 资源时，可以继续引用可用的 `deepin`、`deepin-dark`，但它们只提供自身的配色。GTK 4、libadwaita、Wayland 和沙箱应用的效果按目标支持范围分别确认。
