# 壁纸：获取网络原生分辨率素材

本技能**不绘制壁纸**，也不把生成的占位图当作交付物。用户确认由 Agent 自动挑选、下载并应用后，按主题与屏幕搜索最合适的壁纸，下载、校验、记录来源并应用。只换壁纸用 `theme.py`；创建主题包时才用 `theme_pack.py create` 打包。`create` 只接收本地文件，不联网；下载使用独立的 `wallpaper_source.py`。

用户已明确说“帮我找一张最合适的壁纸并应用”等，视为覆盖自动选图、下载和设置的授权，展示选图理由、来源及作用范围后继续执行，不为同一范围重复确认。用户仅要求搜索、候选或预览时，先展示候选图片与来源，取得应用确认后再执行。这里的确认是操作意愿确认，不要求用户提供版权证明或作许可声明。

## 1. 读取当前屏幕

```bash
python3 "<技能目录>/scripts/wallpaper_source.py" screen
```

依次尝试 `xrandr --current`、`wlr-randr`、`xdpyinfo`，输出实际生效的模式和输出名。多显示器时取 **primary**（无 primary 取第一个已连接输出）；这与会改变的壁纸范围（主显示器当前工作区）一致。检测失败时先让用户在终端运行 `xrandr` 确认，再显式传 `--width/--height`；不要猜一个常见分辨率。

`UOS_THEME_SCREEN=2880x1800` 可在自动化中覆盖检测结果。

## 2. 检索素材

用 Web/图片搜索和浏览工具，结合用户主题、风格、色调与实际屏幕尺寸找图，再访问来源页面定位高清原图。筛选顺序：

1. **主题匹配**：题材、色调、光线与用户偏好一致；兼顾桌面图标和文字的可读性、主体位置及裁切后的构图。
2. **画质与分辨率**：优先清晰、无水印的原图，避免缩略图和付费预览图。宽、高都 ≥ 当前屏幕即可，不需要完全相等。比例尽量相近，差异超过 2% 只提示裁切/留边，不阻止使用；不要放大或拉伸凑尺寸。
3. **可下载性与来源**：找到可访问的 HTTPS 原图直链，并保存来源页面 URL。壁纸站、游戏/影视/动漫官方图、截图和同人作品都可按用户偏好参与选择，不因题材或站点类别一律排除。下载失败时换直链或下一张合适候选。

个人桌面使用不强制核验版权，不把 CC0、公有领域或可再分发许可作为筛选门槛，也不因许可不明停止搜索、下载或应用。作者与许可仅在页面明确提供时记录，未知留空，不编造许可，也不把用户确认写成版权许可。用户另有商用或对外发布要求时，再按该用途处理素材条件。

## 3. 下载与校验

```bash
python3 "<技能目录>/scripts/wallpaper_source.py" fetch \
  --url "https://…/wallpaper.jpg" \
  --output "/绝对路径/wallpaper.jpg" \
  --source-page "https://…/page" --execute
```

不带 `--execute` 时只展示检测到的屏幕、HEAD 探测结果和将要执行的校验，不写文件。执行时强制：

- 仅 HTTPS；重定向到非 HTTPS 直接拒绝；拒绝带凭据的 URL。
- 返回 `Content-Type: image/*`，大小 ≤ 64 MiB，扩展名与真实格式一致。
- 宽、高 ≥ 屏幕；必须能解析尺寸（标准 PNG/JPEG/WebP/BMP）。宽高比只计算偏差并给出提示（2% 内视为接近），不会阻止下载。
- `--license`、`--author` 可选，只填写已知信息；省略或空白许可记录为 `null`，不阻止下载。脚本不判断许可。
- 输出旁生成 `<文件名>.source.json`：URL、最终 URL、作者、许可、来源页、抓取时间、屏幕、图片尺寸、字节数和 SHA-256；未知的作者、许可为 `null`。

已有本地图片（用户提供或浏览器下载）可只做只读校验：

```bash
python3 "<技能目录>/scripts/wallpaper_source.py" check --path "/绝对路径/wallpaper.jpg"
```

尺寸不足时**换素材**，不要放大；比例与屏幕差异较大时仍可使用，但要先说明裁切/留边，并在有更接近比例的选择时优先换图。

## 4. 应用壁纸或生成主题包

只换壁纸时，按 [requests.md](requests.md) 写入仅含本地壁纸路径的请求 JSON（默认主显示器当前工作区）：

```json
{"wallpaper": "/绝对路径/wallpaper.jpg"}
```

```bash
python3 "<技能目录>/scripts/theme.py" plan --request "/绝对路径/wallpaper-request.json"
python3 "<技能目录>/scripts/theme.py" apply --plan-id "plan-返回的真实ID"
python3 "<技能目录>/scripts/theme.py" apply --plan-id "plan-返回的真实ID" --execute
python3 "<技能目录>/scripts/theme.py" verify --change-id "change-返回的真实ID"
```

先展示计划与作用范围，`execute_ready=true` 且用户已有授权覆盖应用时继续 `--execute`，完成后告知用于恢复的 change ID。无需为单独换壁纸创建或安装主题包。

创建完整主题包时，把下载路径写进设计规范的 `wallpaper`，然后按 [package.md](package.md) 生成、安装和激活：

```json
{"id": "xianjian-yujian", "wallpaper": "/绝对路径/wallpaper.jpg"}
```

`create` 会把图片复制到 `wallpapers/`，把尺寸写入 manifest，并把来源记录复制为 `wallpapers/<文件名>.source.json`、同时写入 `manifest.components.wallpaper.source`。侧车摘要与图片不一致、或包内来源记录被改动时，`validate`/`install` 会拒绝继续。没有侧车的本地素材仍然可用，但 manifest 不会声称有网络来源。

若图片小于当前屏幕，`create` 会在 `warnings` 中提示；这不会阻止已在别处验证过的包生成，但不应把它当作最终交付。

## 5. 验收

应用后读回壁纸 URI，并校验文件 SHA-256 与计划或包内文件一致；有桌面截图能力时再查看实际桌面，区分“URI 已读回”和“视觉已确认”。默认只改动主显示器当前工作区；指定显示器时以请求中的真实名称为准。

## 失败处理

| 现象 | 处理 |
|---|---|
| 无法读取分辨率 | 用户在终端运行 `xrandr` 确认，传 `--width/--height`；不要猜测 |
| 图片小于屏幕 | 换一张宽高都 ≥ 屏幕的素材；不要放大 |
| 比例与屏幕差异较大 | 仍可使用；说明会裁切/留边，并在可选素材中优先换更接近屏幕比例的一张 |
| 403/404/重定向到 HTML | 从来源页找可访问的高清直链，或继续选择下一张合适候选；不绕过登录或付费访问限制 |
| 作者或许可未知 | 留空相应元数据；个人桌面使用可沿用用户确认继续，不要求版权证明 |
| 来源记录摘要不一致 | 图片被替换或侧车被编辑；重新 `fetch`，不要手改侧车 |
