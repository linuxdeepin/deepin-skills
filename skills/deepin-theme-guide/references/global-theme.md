# 全局主题的编写与存放规则

DDE 全局主题由一个主题目录和其中的 `index.theme` 组合配置组成。配置负责选择已有应用样式、图标、字体、光标及壁纸，控制中心以这套组合为一个主题选项。

## 主题目录放在哪里

编写时先在工作目录中建立 `<主题 ID>/`。默认按用户主题组织；需要系统预装时再采用系统位置。

| 用途 | 主题根目录 |
| --- | --- |
| 工作目录 | `<工作目录>/<主题 ID>/` |
| 当前用户安装 | `~/.config/dde-appearance/deepin-themes/<主题 ID>/` |
| 系统安装 | `/usr/share/deepin-themes/<主题 ID>/` |

用户配置根目录可以由 `$XDG_CONFIG_HOME` 指定。DDE 也可能识别用户共享数据目录下的 `deepin-themes/` 等位置；新主题优先使用上述用户安装位置，并以 Appearance1 实际识别结果为准。

例如主题 ID 为 `aurora`，工作目录中的文件与用途如下：

| 相对主题根目录的文件 | 用途与要求 |
| --- | --- |
| `index.theme` | 全局主题入口，包含元信息和亮暗配置 |
| `cover.png` | 示例预览文件名，由 `Example` 引用；需要真实可用的图片 |
| `wallpapers/light.jpg` | 示例亮色壁纸；复用外部持久路径时可省略此文件 |
| `wallpapers/dark.jpg` | 示例暗色壁纸；也可与亮色共用一张图片 |

安装时保留主题目录内的相对关系。全局配置放在 `deepin-themes/`；已有 GTK 样式、图标、字体和光标仍放在各自的资源目录，位置见 [资源选择](resources.md)。

## 从模板编写

以 [index.theme 模板](../assets/index.theme) 为起点，将其保存到新主题目录。模板使用 `aurora` 作为目录示意，引用 `cover.png` 和两张壁纸；这些图片由制作任务提供或改为已有资源引用。

模板中的 `deepin`、`deepin-dark`、`bloom`、字体名称及活动色都是填写示意。根据已选资源替换，不能把模板中出现的名称当成目标机器已经安装。已有基础全局主题的资源组合也可以沿用，但新主题应采用独立 ID。

编写顺序是：填写主题元信息，填写默认分组的完整组合，再填写暗色分组中不同的部分。

## 主题身份与元信息

| 项目 | 填写规则 |
| --- | --- |
| 目录 ID | 使用稳定、独立的名称，例如 `aurora`；与内置主题同 ID 会形成覆盖，而不是新增选项 |
| `[Deepin Theme]` | 全局主题元信息分组 |
| `Name`、`Comment` | 显示名称和说明；可增加 `Name[zh_CN]`、`Comment[zh_CN]` 等本地化值 |
| `Example` | 预览图片引用，例如 `cover.png` |
| `DefaultTheme` | 指向默认配置分组；模板引用 `[DefaultTheme]` |
| `DarkTheme` | 指向暗色配置分组；模板引用 `[DarkTheme]` |
| `Hidden` | 通常使用 `false`，使主题可作为用户选择项 |

主题 ID 来自目录名，与显示名称和翻译无关。选择 `aurora.light`、`aurora.dark` 分别应用亮、暗模式；不要创建名为 `aurora.light` 和 `aurora.dark` 的两个全局主题目录。

`DefaultTheme=Day`、`DarkTheme=Night` 也合法，分别表示读取 `[Day]`、`[Night]`。字段名固定，右侧是实际分组名引用。双模式主题需要两个有效引用；自动模式的使用取决于桌面设置。

## 亮暗分组填写什么

| 字段 | 应填内容 | 选择规则 |
| --- | --- | --- |
| `AppTheme` | 已有应用样式名称 | 亮暗分别选择对应变体，例如可用的 `deepin` / `deepin-dark` |
| `IconTheme` | 已有图标主题名称 | 按图标资源列表选择，填写资源名而非目录路径 |
| `CursorTheme` | 已有光标主题名称 | 从光标资源列表独立选择，不要求与图标名称一致 |
| `StandardFont` | 已安装的标准字体族名 | 直接填写完整族名，可包含空格 |
| `MonospaceFont` | 已安装的等宽字体族名 | 与标准字体分开选择 |
| `FontSize` | 字号点数 | 例如 `10.5`，单位为 point |
| `ActiveColor` | 当前模式活动色 | 例如 `#1F6EE7`；亮暗可分别指定 |
| `Wallpaper` | 当前模式壁纸引用 | 使用主题内相对路径、有效绝对路径或文件 URI |
| `LockBackground` | 可选锁屏背景引用 | 按需要指定，可复用壁纸 |
| `WindowRadius`、`WindowOpacity` | 可选窗口外观参数 | 使用目标桌面支持的值 |

字体方案由两个字体族和字号共同组成，没有统一的 `FontTheme` 字段。图标、字体、光标资源的内部组织由它们各自的规范负责，全局配置只记录选择结果。

复用已有应用样式时保留其配色特点。`ActiveColor` 不会自动改变所有应用样式中的颜色；需要为 GTK 补充对应配色时，读取 [GTK 主题适配](gtk-adaptation.md)。设置发布和 Qt 调色板等技术原理见 [主题生效机制](theme-mechanism.md)。

## 亮暗继承规则

默认分组写完整的资源组合。暗色分组只需要覆盖不同的项，通常是 `AppTheme`、`ActiveColor` 和 `Wallpaper`；图标、光标、字体及字号可继承默认分组。暗色需要另一套图标或字体时，也可以在暗色分组明确指定。

暗色某项为空时，从默认分组取同名项；非空但无效的资源名不属于继承。两个分组都缺少某个普通外观项时，结果可能沿用用户原设置，因此完整组合应在默认分组明确填写这些项。

## 文件引用与交付

- 主题内壁纸以主题根目录为相对路径基准；复制安装整个目录后，相对引用保持有效。
- 复用系统壁纸时，可以使用持久的绝对路径或文件 URI，并将对应资源包列为依赖。不要依赖临时目录。
- 预览与壁纸可以复用已有图片，缺少图片时应补齐真实资源或修改引用，不能只留下文件名。
- 图标、字体和光标既可由系统资源包提供，也可由用户资源目录提供；全局主题中仍只写所选名称。
- 跨机器分发时列出所选资源与依赖包。用户目录的同 ID 配置可能覆盖系统版本，新主题应避免无意复用其他主题 ID。

交付时给出工作目录、目标安装目录、各资源选择及 `主题ID.light` / `主题ID.dark` 选择值。需要查询主题是否可选或实际应用时，使用 `deepin-desktop-environment` Skill 的 Appearance1 外观服务。
